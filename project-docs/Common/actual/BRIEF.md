# Бриф заказчика — FOT System

**Формат:** документ для отправки заказчику (бриф).  
**Назначение:** собрать ответы до финальной оценки.  

> Поля «Ответ заказчика» — заполняет клиент.  
> Блок **G** — прозрачный чеклист для выбора формата работы.

## G. Граница: инженерия vs «вайбкодинг» *(внутренний блок)*

Ответы здесь определяют, можно ли делать **простое кастомное приложение** или нужна **инженерная разработка** (тесты, контракты, миграции, поддержка).  
Критерий: если ≥3 пункта из «инженерия» — закладываем полный цикл, а не легковесный прототип. 

| # | Вопрос | Ответ | → Инженерия если… |
|---|--------|-------|-------------------|
| G1 | **Точность расчётов ФОТ** — ошибка в 1–2% допустима или нужна сверка «до рубля» с Excel/бухгалтерией? | | До рубля, сверка с бухгалтерией |
| G2 | **3–5 человек одновременно** правят график/явку — это ежедневная реальность или редкость? | | Ежедневно, без потери данных |
| G3 | **Срок жизни системы** — 3–6 месяцев «пока не привыкнем» или **1–3+ года** с накоплением истории? | | 1+ год, история критична |
| G4 | **Кто поддерживает после запуска** — вы сами, штатный IT, или исполнитель на сопровождении? | | Нужна документация, передача, сопровождение |
| G5 | **Правила расчёта** (4 категории, комиссии, % от выручки) — будут **меняться каждый квартал** или стабильны? | | Частые изменения правил → тесты + версионирование |
| G6 | **Импорт истории** — сколько месяцев/строк в текущих таблицах? | | >500 строк или сложные формулы |
| G7 | **Аудит и споры** — бывают разногласия «кто вышел / сколько начислили»? Нужен неизменяемый лог? | | Да, нужен аудит |
| G8 | **Интеграции** — 1С, банк, мессенджеры, выгрузка в бухгалтерию в ближайшие 6 мес.? | | Любая интеграция в roadmap |
| G9 | **Доступность** — простой простоя недопустим (производство встанет) или «подождут час»? | | Критичный uptime |
| G10 | **Мобильный ввод** в цехе при плохом интернете — нужен offline или достаточно online? | | Offline / sync |
| G11 | **Безопасность данных** — ФИО, ставки, выручка: достаточно пароля или разграничение ролей + шифрование? | | Роли, 152-ФЗ, разграничение |
| G12 | **Расширение scope** — планируются склады, несколько цехов, KPI по продуктам, автоматизация заказов? | | Явный roadmap расширений |
| G13 | **Приёмка** — «посмотрели, ок» или **чеклист по цифрам** (сверка ФОТ за тестовый месяц)? | | Сверка цифр, формальная приёмка |
| G14 | **Хранение «под капотом»** — заказчик согласен на **нормальную БД**, или настаивает видеть Google Sheets как backend? | | Sheets как source of truth = риск, нужна инженерия поверх |
| G15 | **Бюджет vs риск** — приоритет «быстро и дёшево прототип» или «один раз нормально, чтобы не переделывать»? | | «Один раз нормально» |
