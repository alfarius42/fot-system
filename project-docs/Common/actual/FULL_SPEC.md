# Full Spec — MVP (из ТЗ заказчика)

Проект: **Система планирования смен и учёта ФОТ производства**  
Источник: [`../source/tz-fot-system.pdf`](../source/tz-fot-system.pdf)  
Статус: **черновик для оценки** — открытые вопросы в [`BRIEF.md`](BRIEF.md)

## 1. Формат реализации

- **Единое веб-приложение** (сайт с логином), не Excel/Google Таблица «на виду».
- Доступ с телефона и разных устройств, без установки ПО.
- **3–5 пользователей** одновременно, без конфликтов при редактировании.
- Ввод данных — через **формы внутри приложения**, не прямое редактирование таблицы.
- Хранение данных (Google Sheets / БД / иное) — на усмотрение исполнителя, **не видно пользователю**.

## 2. Справочники

### 2.1 Должности

- Редактируемый список.
- Минимум: повар, мойщица, уборщица, фасовщик, комплектовщик.
- Перечень будет пополняться.

### 2.2 Сотрудники

Каждый сотрудник привязан к:

- должности;
- **категории** (см. ниже);
- **ставке** — индивидуальной или по умолчанию для должности (с возможностью переопределения).

### 2.3 Категории сотрудников

| # | Категория | Расчёт в системе |
|---|-----------|------------------|
| 1 | Свой штат, нал | Зарплата полностью наличными |
| 2 | Свой штат, официальный | Часть официально + часть нал; **внутри приложения — только общая сумма/ставка** |
| 3 | Аутсорс А (по счёту) | Компания платит своим; нам счёт по безналу за смены. **Нужна детализация по каждому сотруднику** (кто вышел, в какую смену) для сверки со счётом |
| 4 | Аутсорс Б (по комиссии) | Сотруднику платим нал сами; компании — комиссия за человеко-день по безналу (пример: 10 чел × 10 дней = 100 человеко-смен) |

## 3. Планирование смен (график на месяц)

- Руководитель кухни в начале месяца составляет **базовый график**:
  - расстановка сотрудников по **датам, сменам, участкам цеха**;
  - приоритет — **свои** (нал + официальные); аутсорс — подстраховка при нехватке;
  - параллельно — **целевое количество единиц продукции** к выпуску (по дням / на месяц).
- Система на основе графика показывает:
  - численность людей на каждом **участке** (по дням);
  - **плановую стоимость** смены / дня / недели / месяца (ФОТ);
  - те же показатели **в разрезе количества человек**.

## 4. Оперативная корректировка (день в день)

- Заказ на производство поступает **за день до факта**.
- Руководителю нужно:
  - посмотреть график на **завтра** — кто стоит, есть ли нехватка;
  - при необходимости **вызвать доп. человека** и отметить источник: свой сверхурочно / аутсорс А / аутсорс Б;
  - зафиксировать **план vs факт по явке** (кто вышел, кто нет).

## 5. Показатели и контроль (дашборд)

**Основной раздел** с фильтрами: период, категория сотрудников, участок цеха.

Динамика (день / неделя / месяц):

| Показатель | Источник |
|------------|----------|
| ФОТ факт vs план, ₽ | Расчёт из графика и явки |
| ФОТ как % от выручки (цель ≤ 15%) | ФОТ + выручка |
| Выручка план vs факт, ₽ | **Ручной ввод** |
| Единиц продукции в день — план vs факт | **Ручной ввод** |
| Численность по категориям (свои / аутсорс А / Б) | Из графика и явки |

**Отдельная вкладка/раздел того же приложения** — форма ежедневного ввода:

- явка сотрудников по факту;
- выручка за день;
- количество произведённых единиц;
- вызов доп. человека при нехватке.

Переход дашборд ↔ ввод **без выхода из приложения**.

## 6. Обязанности исполнителя (из ТЗ)

1. Спроектировать структуру данных (сотрудники, ставки, график, факт явки, ежедневные показатели) и связи.
2. Настроить дашборд с перечисленными KPI и фильтрами.
3. Удобный ввод для нескольких пользователей без конфликтов.
4. Краткая инструкция (факт, новый сотрудник и т.д.).

## 7. Вне scope / обсуждается

- Внешний вид, порядок полей, мелкие уточнения логики — в переписке.
- **Приёмка и итерации правок** — уточнить, входят ли в оценку.

## 8. Открытые решения

См. [`BRIEF.md`](BRIEF.md). Критичные для оценки:

- количество участков цеха и смен;
- модель ставки (за смену / час / день);
- правила комиссии аутсорс Б;
- роли и права пользователей;
- предпочтения по хостингу и стеку.
